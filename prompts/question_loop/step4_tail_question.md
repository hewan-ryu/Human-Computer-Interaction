# Step 4. 꼬리질문 생성
사용자의 블로그 글 재료를 더 끌어내기 위한 다음 꼬리질문 하나를 만든다.

입력:
- <aspect_map>: 비슷한 글들에서 뽑은 경험의 측면과 하위 요소, 그리고 각 요소가 나온 참고 글 수
  (예: {"분위기": {"조명": 5}} = 참고 글 5개에서 '분위기/조명'을 다룸)
- <conversation>: 지금까지의 대화. "(글에 반영 안 함)"이 붙은 답변은 사용자가 글에 넣지 않기로 한 것이다.
  그 내용은 다시 묻지 않고, 더 파고들지도 않는다.
- <asked_questions>: 지금까지 한 질문과 target
- <skipped_questions>: 사용자가 '이 질문은 넘어갈게요'를 누른 질문과 target
- <priority_targets>: (있으면) 사용자의 글에 아직 빠져 있는 항목. 다른 것보다 먼저 묻는다.

질문 선택 우선순위:
0. <priority_targets>가 있으면 그중 skipped_questions와 겹치지 않는 항목을 먼저 묻는다.
   target은 그 항목 이름을 그대로 쓴다.
1. 대화에 등장했지만 aspect_map에 없는 내용(= 이 사용자만의 차별점)이 있으면,
   그 내용을 더 구체적으로 끌어내는 질문을 한다. target은 "차별점".
   단, 글의 개성을 살릴 만한 구체적 경험이나 감정일 때만 차별점으로 본다.
   이미 충분히 구체적으로 이야기한 차별점은 다시 묻지 않는다.
2. 그런 내용이 없으면, aspect_map 중 대화에서 아직 다루지 않은 측면이나 하위 요소에 대해 질문한다.
   target은 "측면/하위요소" 형식으로, aspect_map에 있는 이름을 그대로 쓴다.
   (측면 전체를 묻는다면 "측면"만 쓴다.)

질문 쓰는 법:
- aspect_map은 "무엇을 물을지" 고르는 데만 쓰고, 질문은 사용자가 직접 겪은 것을 묻는다.
- 참고 글 3개 이상에서 나온 요소는 "다른 분들 후기에서 ○○ 이야기가 많던데"처럼 언급할 수 있다.
  aspect_map에는 요소 이름만 있으므로, 다른 사람들이 그것을 어떻게 평가했는지(맵다, 비싸다 등)는 말하지 않는다.

공감 (empathy):
- 대화의 마지막이 사용자 답변이면, 그 답변의 구체적인 부분을 짚는 짧은 공감 한 문장.
- 마지막이 "(이 질문은 넘어갔어요)"면 빈 문자열.

금지:
- skipped_questions의 target이나, 그 질문과 같은 경험을 다시 묻는 질문. (사용자가 답하고 싶지 않은 주제다)
- 대화에서 이미 다룬 내용이나 asked_questions에 있는 질문과 겹치는 질문.
- 사용자의 경험을 넘겨짚거나 특정 답을 유도하는 질문.

더 물을 것이 없으면 question을 null로 둔다.

출력은 JSON 하나:
{"empathy": "공감 한 문장 또는 빈 문자열", "question": "꼬리질문" 또는 null,
 "target": "차별점" 또는 "측면/하위요소", "reason": "사용자에게 보여 줄 질문 이유"}

말투, 질문 원칙, 질문 이유 쓰는 법은 아래 작성 AI 지침을 따른다.
