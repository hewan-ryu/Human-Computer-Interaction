# Step 5. 답변 평가 및 추가질문
방금 한 질문에 대한 사용자 답변이 블로그 글로 쓰기에 충분히 구체적인지 판단하고,
부족하면 답변을 더 구체화하는 추가질문 하나를 만든다.

입력:
- <tail_question>: 이번에 다루는 꼬리질문과 target
- <last_question>: 사용자가 방금 답한 질문 (꼬리질문 또는 앞선 추가질문)
- <answer>: 사용자 답변
- <conversation>: 지금까지의 대화
- <references>: 다른 글쓴이들이 같은 측면에서 쓴 글 (없을 수 있음)

판단 기준:
- 구체적인 장면, 감각, 이유, 비교, 그때의 감정 중 글에 살릴 만한 디테일이 있는가.
- 이미 충분하면 need_followup은 false, question과 reason은 null.

추가질문 규칙:
- 부족한 디테일 한 가지를 열린 질문으로 묻는다. (예: 구체적 장면, 감각, 이유, 비교, 감정)
- references는 다른 글쓴이들이 이 측면에서 어떤 디테일을 썼는지 파악하는 데 쓴다.
  - 질문에서 "다른 분들은 ~하던데, 직접은 어땠어요?"처럼 언급할 수 있다.
    단, references에 실제로 있는 내용만, 내 말로 바꿔서 말한다.
    3개 이상의 references에 있을 때만 "많은 분들이"라고 한다.
  - 사용자의 경험을 넘겨짚는 질문(예: "조명이 따뜻했죠?")은 하지 않는다.
- 대화에서 이미 다룬 내용은 묻지 않는다.

공감 (empathy): 답변의 구체적인 부분을 짚는 짧은 공감 한 문장. 추가질문이 없으면 빈 문자열.

출력은 JSON 하나:
{"need_followup": true 또는 false, "empathy": "공감 한 문장 또는 빈 문자열",
 "question": "추가질문" 또는 null, "reason": "사용자에게 보여 줄 질문 이유" 또는 null}

말투, 질문 원칙, 질문 이유 쓰는 법은 아래 작성 AI 지침을 따른다.
